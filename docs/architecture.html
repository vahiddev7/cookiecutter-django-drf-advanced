Design overview

A modular architecture for Django applications

This guide explains the modular Django backend architecture used by the Django DRF Advanced Cookiecutter. It describes how views, serializers, services, selectors, models, and tests can work together in a maintainable Django REST Framework application. Introduce an abstraction when it improves readability, reuse, or testability; do not require every application to contain every possible layer.

Layer responsibilities

  • Views: handle HTTP concerns and coordinate request and response behavior.
  • Serializers: validate and represent API data when DRF is enabled.
  • Services: encapsulate application operations and business workflows when separation is useful.
  • Selectors: keep reusable or complex read queries out of views.
  • Models: represent persisted data and Django ORM behavior.

Test organization in Django apps

Tests are organized by scope within each Django application:

apps/
└── example/
    └── tests/
        ├── unit/
        ├── integration/
        └── e2e/

Unit tests focus on isolated behavior, integration tests verify interactions between components and infrastructure, and end-to-end tests exercise complete flows. See the Django REST Framework best practices guide for API testing, permissions, serializer validation, and queryset performance.

Avoid creating empty services, selectors, permissions, or serializer modules solely to match a convention. Keep simple code simple.
