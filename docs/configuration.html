Template options

Configure your generated Django project

The template uses Cookiecutter prompts to include only the integrations selected for a project. The available options are defined in the repository's cookiecutter.json.

Django REST Framework

Enable or disable Django REST Framework. The authentication application is generated when DRF is enabled.

API documentation

Choose whether to include the configured Swagger/OpenAPI support. This option is relevant when DRF is enabled.

Docker

Choose whether the generated project includes the Docker development setup and compose configuration.

Database engine

Select one of the configured database backends:

  • PostgreSQL
  • MySQL
  • SQLite
  • SQL Server

Database drivers and operational requirements differ. Verify the selected backend in your target environment.

Celery, message broker, and Flower

Enable Celery for background task processing, then select Redis or RabbitMQ as the broker. When Celery is enabled, the generated Docker Compose setup also includes Flower at http://localhost:5555 for monitoring workers and tasks and using Flower's supported task controls. Access is protected by a generated FLOWER_BASIC_AUTH credential, and Flower state is persisted in a named volume. The dashboard binds to localhost only by default; do not expose it publicly without HTTPS and an access-controlled reverse proxy. When Celery is disabled, neither Flower nor its dependency is included.

Cloud storage

Choose local filesystem storage, AWS S3 (including S3-compatible endpoints), Silo (a self-hosted MinIO-compatible S3 server), Google Cloud Storage, or Azure Blob Storage. AWS S3, Google Cloud Storage, and Azure Blob Storage are external managed services, so Docker Compose does not start containers for them; Django connects to them using the configured endpoint and credentials or workload identity. Selecting Silo is the local/self-hosted option and adds a pinned Docker Compose service, persistent data volume, health check, and automatic bucket initialization. Its S3 API listens on port 9000 and its console on port 9001. Generated credentials are for local development; use TLS, private networking, scoped application credentials, and managed secrets in production. When a cloud provider is selected, its media and static-file settings live in config/settings/storage.py, separate from the base settings module; that file is omitted entirely for the local-filesystem option. Configure credentials through environment variables or workload identity; never commit secrets. Run python manage.py collectstatic after configuring the provider.

Logging and error monitoring

Console logging is configured separately from the base settings and its verbosity is controlled by LOG_LEVEL. Sentry is optional: select it during project generation. The dedicated config/settings/sentry.py file is included only when Sentry is enabled; when disabled, it is omitted. Configure SENTRY_DSN and sampling settings through environment variables. Sentry remains inactive when no DSN is provided.

Choosing options

Start with the smallest set of integrations your application needs. You can add infrastructure as requirements become clearer, but changes to generated configuration should be tested against the selected database and service combination.
