Project lifecycle

Releases, versioning, and compatibility

Each release is a versioned snapshot of the Cookiecutter template. The generated project is copied into a new directory; it is not automatically upgraded when the template receives a newer release.

Versioning policy

Releases use Semantic Versioning with tags in the form vMAJOR.MINOR.PATCH.

  • MAJOR: incompatible changes to prompts, generated project structure, configuration contracts, or documented behavior.
  • MINOR: backward-compatible features, integrations, or optional capabilities.
  • PATCH: backward-compatible fixes, dependency corrections, documentation improvements, and CI maintenance.

Because this is a generator, compatibility includes both the Cookiecutter prompt interface and the files emitted for each supported option combination. A change can be breaking even if the template repository itself still runs.

How a release is published

  1. Merge the reviewed change into master after required CI checks pass.
  2. Update CHANGELOG.md with user-visible changes and move the relevant entries out of Unreleased.
  3. Create and push an annotated semantic version tag, for example v1.2.0.
  4. The release workflow generates minimal and full-featured projects, validates key generated files and Docker Compose configuration, and checks documentation.
  5. If validation succeeds, GitHub creates a Release from the tag with automatically generated release notes.
git checkout master
git pull --ff-only
git tag -a v1.2.0 -m "Release v1.2.0"
git push origin v1.2.0

Do not create a tag for an unreviewed or failing commit. A failed validation blocks publication. Existing releases are never overwritten by the workflow.

Using a pinned template version

For reproducible project generation, use a release tag rather than the moving default branch:

cookiecutter https://github.com/vahiddev7/cookiecutter-django-drf-advanced --checkout v1.2.0

Replace the example tag with a published version. Review the release notes before adopting a new version.

Updating an existing generated project

Cookiecutter does not continuously synchronize an already-generated project with this repository. Do not regenerate over a working application as an upgrade strategy. Compare the release notes and template diff, then apply relevant changes deliberately, preserving application code, environment-specific configuration, and secrets.

Release artifacts and support

GitHub Releases provide the source archive for each tag and the generated release notes. No binary distribution or hosted runtime is implied. Report reproducible defects with the release tag, Python version, operating system, and sanitized Cookiecutter answers.

See contribution guidelines, security policy, and the changelog.
